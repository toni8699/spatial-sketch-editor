## Decisions (locked before coding)

1. **Spine replaces ribbon domain switcher.** `WorkspaceRibbon.svelte` Zone A Scene\|Camera moves to new vertical Spine; ribbon keeps Plan\|3D + contextual tools only. No dual domain controls during transition.
2. **PLATE Light becomes `DEFAULT_THEME`.** Navy becomes a variant; variants must not redefine component roles. Add `plate-light` theme id to `THEMES` + `tokens.css` override block + `app.html` allowlist (CI-pinned by `tests/lib/editor/theme-registry.test.ts`).
3. **Plan tokens untouched.** Only surrounding chrome tokens change; `--editor-plan-*` invariant stays (scene-palette contract test must keep passing).
4. **Navigator `Ends` row removed by default** per slice README preferred fix; `Boundary Junctions (n)` + global Junctions page remain the inventories. No second Junction-selection authority.
5. **Lane set immutable.** Five Timeline lanes render per scope (no-flow = header + empty 288px body, collapsed = 48px transport strip, no scrubber); Roll stays quiet `0°`. Weight/grouping/collapse is free; deletion is a Camera product decision, out of scope.
6. **P26 host = shell state, not document state.** Contextual instrument (e.g. Wall Elevation) replaces/focuses central Paper with visible return to owning durable view; never a third peer view.
7. **Room rotation handle: gate, don't invent (locked).** In wall-first Layout docs the selected-Room rotation arm/handle is not painted at all (paint seam: `layout/plan-overlays.ts` ~1318; drag path in `layout/LayoutPlanViewport.svelte`). Wall-first Rooms have no yaw semantics, so a painted-but-dead handle is a mute control that fails the trust test. Scene staging rotation arms (`plan-overlays.ts` ~518/532) and P10 layout-object yaw arms (~560/576) are untouched — those owners support yaw. No new wall-first Room rotation capability; no keyboard reachability added. (Resolves the slice README carried row via its option A: gate mark to owners supporting yaw.)
