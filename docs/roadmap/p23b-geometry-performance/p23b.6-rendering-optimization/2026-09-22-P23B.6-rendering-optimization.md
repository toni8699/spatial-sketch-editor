What S6 **guarantees**: within ONE compile, every name the live state hands back for that compile
(the compile object or its `$state` proxy) resolves to the ONE `derivedWallMeshes` entry the compile

and builds the full Wall-mesh set: every accepted edit, and every pointermove of a whole-Room move
(§2.3). Cross-compile reuse of unchanged sub-parts is M-3m (§5.1), and it composes with S6 by
resolving through the same `wallMeshCacheKey`, with no second cache owner.

Readings that shape the plan — each is a hypothesis for S1, not a result:

- **The adapter is not a cost.** 40 `BufferGeometry` constructions take about 0.2 ms, and Plan
  view mounts no 3D scene at all.
- **The proxy is a multiplier.** The raw Plan render model is 0.07–0.35 ms; through the `$state`
  proxy it is 4–23 ms, registering 8–21 k reactive dependencies. Curvature raises the node count
  by ~1.6× and the dependency count by ~2.7×.
- **Curvature roughly doubles the canonical compile** (12.6 → 27.9 ms). That cost is outside this
  slice (§13).
- **M-3m is reachable but modest.** Whole-Room move gives ~90 % value-equal Walls. The saving is
  bounded by the mesh-set build (12–19 ms node), and a naive key eats 20–40 % of it.

### 2.2 Mesh-builder input set (canonical wall-first path)

`buildStandaloneWallMesh(wall, floorElevation, ends, options)` depends on exactly these inputs:

- **the whole `CompiledPhysicalWall`**: `samples`, `thickness`, `height`, `sections`, `solidSpans`,
  hosted `openings`, `wallId`, `startJunctionId`/`endJunctionId`, bounds, polylines;
- **the Wall's floor elevation**: `geometry.floors[wall.floorId].elevation`;
- **the resolved ends**: `legJoinsByWall(geometry.junctions).get(wallId)`, which carry clip
  distances, corners, face-suppression interfaces and their bands;
- **module constants**: default weld tolerance and miter limit, and the default `classify` →
  material groups. `buildWallMeshesByRoom` passes no options.

Every other dependency reaches the mesh only through these inputs:

- connected Junctions and adjacent Walls, through the resolved ends;
- hosted Openings, through `wall.openings`, `sections` and `solidSpans`;
- dimensions, through `thickness`, `height` and `samples`;
- material groups, through `classify` and the surface kinds.

S3b must PROVE this closure: the builder has no module-level mutable state and reads nothing
beyond its arguments and constants. It must also land the refusal matrix (§7 OR-9). Legacy
`buildRoomWallMesh` is out of M-3m's scope and stays whole-set.

### 5.1 M-3m — cross-generation prepared-mesh reuse from a reference generation (conditional; ADAPT)

```text
D-0  NO REUSE BY COMPILED OBJECT IDENTITY. A candidate's compiled Walls are always new objects
     (F-P9), so an identity key never hits and would pass every equivalence oracle while delivering
     nothing. EQ-5's by-reference sharing is a SOURCE-document fact, not a compiled one. Reuse is
     justified only by VALUE equality of the traced inputs (§2.2).
D-1  THE CONTRACT IS THE GATE. A Wall-id match never admits reuse. S3b traces and proves the
     closure of §2.2 and lands the refusal matrix; without it M-3m is not admitted (AB-9).
D-2  THREE LAYERS, THREE IDENTITIES. M-3m reuses `IndexedWallMesh` (layer 3) ONLY — never compiled
     geometry, never `BufferGeometry`.
D-3  GEOMETRY INVALIDATION ONLY (Sweet Home 3D split SV; Blueprint3D contrast SV).
D-4  ONE OWNER, NO NEW RETENTION. No new cache. On a MISS for generation G', the preparation takes
     ONE caller-supplied REFERENCE GENERATION — the one currently installed, resolved through
     `wallMeshCacheKey` so the S6 mapping composes. For each Wall w it reuses the reference entry's
     mesh iff w's inputs in G' EQUAL w's inputs in the reference. The reference is already alive,
     so there is no added retention and no cross-gesture store. The entry is keyed on G' as today;
     shared `IndexedWallMesh` objects are immutable data released with the last entry holding them.
D-5  CONSERVATIVE, FUTURE-PROOF COMPARATOR. Equality covers the WHOLE `CompiledPhysicalWall`
     record (every own field, recursively, full precision, early exit) + floor elevation + the
     Wall's resolved ends + a BUILDER-SIGNATURE tag. A compiled field the comparator has never
     seen is compared like any other, so new P26 fields (top profile, periodic/seam data) refuse
     reuse on change rather than being silently ignored. The comparator must cost measurably less
     than the builds it skips; the planning probe's JSON-string comparison (20–40 % of the build)
     is the ceiling to beat. Legacy room meshes, and any Wall whose build returned issues, are
     never reused.
D-6  FAILURE ISSUES ARE NOT REUSED. `issues` are recomputed as today; only successful meshes are
     reused.
D-7  PURE, STATE-FREE PREPARATION (the P26 adaptation). The per-generation build plus reuse lives
     in one renderer-free, Svelte-state-free preparation module with the signature
     `(generation, reference?) → prepared set`. The existing `derivedWallMeshes` cache moves with
     it, still the single owner. `LayoutPreviewState` only supplies the reference and installs
     the result. Nothing in it reads `$state`, effects or Threlte, so the module can be consumed by
     P26's successor viewport as-is.
D-8  NO VIEW STATE IN THE KEY. Camera, projection, cut, peel, lift, mirror, selection and hover are
     never inputs. The builder-signature tag must change whenever the builder's parameter list or
     its derived-input set changes (e.g. a future seam or profile argument).
REJECTED  (i) whole-set reuse keyed on the document (F-P9) · (ii) a per-Wall LRU/pool across
          generations — a second owner plus new retention · (iii) source-document keys — need a full
          source→compiled proof through Junction resolution · (iv) translation-invariant reuse of
          moved Walls — changes world-space mesh data
```

### 5.2 S-R — compiled-generation reactive representation (conditional on S1; RETAIN)

The compiled `geometry` and the projected `model` are derived data. They are only ever
replaced wholesale — geometry by `installWallGeometry` (its single writer), the model by the
install/restore paths — and a source-pattern search found no in-place writes. Yet the live
`$state` graph deep-proxies them. Every first read after an install builds a proxy tree of
30–50 k nodes, and every reactive read registers per-field dependencies.

S-R holds both fields as **raw references**: replaced wholesale, and reactive at the field, not
per element. That is done through Svelte 5's `$state.raw` or through a holder the proxy does not
enter. The choice is S-R's design step, in Svelte 5 runes idiom, and it covers both mounts
(`EditorApp`, `MuseumEditorApp`). Consequences S-R must carry:

- the S6 mapping becomes dormant, because the live read IS the compile object. It stays in place;
  retiring it is a separate simplification, not part of S-R;
- the S6 regression oracle must be re-based on the state exactly as the editor constructs it after
  S-R. Its negative control — a proxied geometry — must still FAIL the old code;
- the snapshot guard stays green;
- every Plan/3D/Inspector consumer still updates on each install, restore, Undo, Redo, import
  and reset;
- the visitor is untouched.

S-R changes no compiled value and no rendering output, and it becomes more valuable under P26.
Reactive/flush cost is owned by this slice (P23B.7's closeout routed it here).

### 5.3 Adapter and GPU — out of scope

The current effect lifecycle is already a correct ownership proof:

- rebuild per generation;
- dispose the previous generation in the effect cleanup and on unmount;
- no `BufferGeometry` reachable from history or snapshots.

This slice keeps that lifecycle UNCHANGED. It adds the lifetime oracle H-5 so the P26 successor
inherits a test, not a mechanism. If S1 finds a 3D-view hitch, it is recorded with its
attribution and routed to P26 P6. No P23B.6 GPU or presented-frame claim is made.

### 5.4 Plan side — recorded only

The raw `buildPlanRenderModel` stays a pure projection, and its cost is negligible. Its PROXIED
cost is an S-R term. `PlanSvg` and the affine projection are left alone, because P26 replaces
that projection authority. S6 of this slice records the post-S-R Plan-side attribution. A
remaining Plan-template term that S1 names is recorded and routed; it is not optimized here.

## 6. History retention (mandatory obligation)

**What is retained today** (traced). Each Layout history entry (`#past` ≤ 100, `#future` ≤ 100,
plain arrays) holds `before: LayoutPreviewSnapshot`. That snapshot holds a cloned project, cloned
issues and the geometry **by reference**. That reference is the live `$state` proxy, so it keeps
alive:

- the compile object;
- whatever lazy proxy tree was built for it;
- through `wallMeshIdentities` (proxy → compile) and `derivedWallMeshes` (compile → entry), that
  compile's full mesh set and pick index.

`BufferGeometry` is never reachable from history: it is adapter-owned and effect-disposed. On the
planning probe's sizes, one curved-40 generation is ~4.6 MB of geometry JSON (heap larger) plus
~0.9 MB of mesh arrays, and history can hold ~200 generations.

This slice must PROVE the following with a deterministic reachability oracle (WeakRef +
forced GC in the node lane; S2 establishes the harness, or records why GC cannot be forced and uses
a counted-reference fallback):

```text
H-1 eviction   the 101st commit releases the oldest entry's compile, its mesh entry and its proxy
H-2 branch     a commit after Undo releases every discarded redo entry
H-3 teardown   document replacement (import/reset) and editor unmount release everything that no
               surviving history entry references (S2 records whether replacement clears history)
H-4 bounded    repeated edit / Undo / Redo cycles never retain more compiled generations than
               past + future + live (+1 gesture baseline while a gesture is open)
H-5 GPU        3D mount: BufferGeometry allocations = disposals + live after edit, Undo, Redo, branch,
               view switch and unmount; none is referenced by a snapshot
H-6 composition  M-3m (if landed): a shared IndexedWallMesh is released with the last generation that
               references it, and no generation holds a reference to another. S-R (if landed):
               retained proxy trees disappear (reported, not required)
H-7 P26 CONTRACT (recorded as the inherited rule, proven for today's owners by H-1…H-6):
               a canonical generation is strongly held ONLY by live state and document-history
               entries; every derived artefact (prepared meshes, pick/snap indexes, and in P26 the
               contextual fragments) is keyed WEAKLY by its generation and never keeps one alive;
               GPU resources are owned by the renderer lifecycle and never reachable from history;
               view/session state (P26's trail) references generations by canonical ID +
               generation number, never by object, and never enters document history
REPORT (advisory)  retained bytes per generation, straight vs curved, and at a full 100-entry stack
```

A history-storage redesign is a SEPARATE, evidence-gated owner decision, routed (§13), never
implemented here. Examples: document-only snapshots with recompile on Undo, or a byte cap.
H-1…H-5 green with a large advisory footprint is recorded as a finding, not fixed.
