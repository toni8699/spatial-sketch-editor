## Guard choice and D-5 refusal contract

The preparation module is pure, state-free and renderer-free. It owns the moved `buildWallMeshesByRoom` path and the existing `derivedWallMeshes` weak cache; there is no second cache or new retention. On a miss, the caller supplies only the currently installed generation as reference, and both generations resolve through `wallMeshCacheKey` so the S6 mapping composes. The module uses the test-time plain-data invariant plus a DEV-only assertion. In DEV, the structural verdict is computed once for the candidate generation and stored with its `PreparedWallMeshSet` in the existing weakly keyed generation cache; a reference generation brings its previously computed verdict from that same entry. The per-Wall comparator does not perform a structural walk. Production relies on `layout-core`'s compiler-owned plain-data output. The independent OR-9 controls keep the structural invariant executable in tests and DEV, including the non-enumerable-field case that `Object.keys` cannot see.

D-5 uses the S1 recursive `Object.keys` comparator on the whole compiled Wall and resolved-end record, with direct equality for floor elevation and the builder-signature tag. A reuse hit requires a successful reference mesh with no issues. Issues are recomputed for each candidate generation. Legacy Room meshes never cross generations, and no object-identity equality or view state participates in the key.

This is the measured choice because the reflective `Reflect.ownKeys` / property-descriptor / `Set` traversal was the cost of the failed first probe, not the S1 comparator itself. The dedicated diagnostic below reports those two costs separately. Keeping the full structural walk on every production Wall comparison would repeat it up to twice per Wall and would reintroduce the observed net loss. The cached DEV verdict preserves the reference-side refusal check without a new cache, strong retention, or per-comparison walk. No mesh-builder file was changed.

The production probe ran on `e11f804ba631ac0c983fa3e1da0d0d4aeb4ce11f`, clean, Node v26.7.0, `NODE_ENV=production`, Vite production mode (`viteDev=false`), Apple M2 / 8 logical CPUs. It used five warmups and fifteen measured samples, twenty fresh compiled candidate generations per path/action, and one prepared currently installed generation as the only reference. The counting unit is **one full-generation preparation**; each Wall's comparison/reuse decision occurs inside that call. The probe writes no baseline or ratchet. Full provenance, p50/p95, refusal counts and diagnostic splits are in the [guard-recheck data](2026-09-26-P23B.6-S3-guard-recheck-data.json).
