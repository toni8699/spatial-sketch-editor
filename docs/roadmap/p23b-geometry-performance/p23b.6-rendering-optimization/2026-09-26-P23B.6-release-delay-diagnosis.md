## 5. Named cause

`buildCorrespondenceComponents` in
`packages/layout-core/src/layout-room-reconciliation.ts:301`, specifically the
whole-document pair loop at `:340–:349`:

```text
faces.forEach × predecessorRoomIds.forEach          (:340–:341)
  pointStrictlyInsidePolygon(face.polygon, witness) (:344, O(face verts))
  polygonsShareInteriorArea(predecessor, face)       (:349, O(a·b) probes +
      O(a·b) edge-crossing loop + two O(n²) ear-clipping interior-point
      derivations in layout-face-extraction.ts:688, :521)
```

Invoked unconditionally for every boundary-role chain at
`packages/layout-core/src/layout-wall-chain.ts:638` (block `:610–:673`).
Zero `p2311Measure` marks exist in `layout-wall-chain.ts`,
`layout-room-reconciliation.ts`, or `layout-face-extraction.ts`, so this block
sits inside the unattributed interval. Its share is PROVEN in node only: about
800 ms of the all-curved commit, against a 2,147 ms browser release p50 (S6).
How much of the remaining browser time it also explains is unverified; the
follow-up fix slice's first step is one browser profile to confirm the split
before any saving is promised. (The P23.1 geometry-edit path
`finalizeWallGeometryCandidate` marks its own gates, but wall-chain commits do
not go through it, so those marks never fire here.)

Per commit on all-curved-40: 10 candidate faces × 10 predecessor rooms = 100
pair tests over sampled curved polygons (2,560 face vertices total), each test
running vertex probes, an edge-pair crossing loop, and ear-clipping interior
derivations — ~776 ms node DEV for correspondence alone inside an ~885 ms plan
(stage split §6). A single independent segment authored in a clear gap, which
creates no face and touches no room, pays the full 100-pair proof.

Secondary (minor, not the cause): `commitWallChain` (`:1387`) and
`commitWallSegment` (`:1497`) pass no `acceptance` to `deriveInstallBundle`, so
every boundary commit compiles twice (plan compile + install compile, ~26 ms).
`finalizeWallGeometryCandidate` threads its acceptance compile through
`applyWallFirstDocumentPlan` (`:1321`); the wall-chain path never adopted that.

## 7. Required, redundant, or avoidable

- **Required:** Room correspondence itself. P23B.3a (Option E, D-12
  reconciliation identity) plus the P23.8 correspondence engine require that a
  boundary commit prove Room identity preservation; the `unionAuthorized`
  gate is the mechanism that keeps independent components from claiming each
  other's rooms. The verdict must stay exact.
- **Redundant:** running the *whole-document* 100-pair proof for operations
  whose affected extent is one new wall and zero changed faces. P23B.7 S3
  already derives per-move affected extents
  (`wallFirstArchitectureAffectedExtent`,
  `packages/layout-core/src/layout-wall-first-precision.ts:1119`) and S4 proves
  scoped verdicts equal whole-document ones — but that machinery serves the
  gesture preflight only; `planWallChain` never consults it.
- **Avoidable:** the per-pair predicate cost has no broadphase (no bbox reject
  before O(a·b) probes), no memoization across commits on the same baseline,
  and no scoping. The algorithm, not the requirement, is the cost.

  closed; its scope never covered wall-chain commits.
- *A new named slice* — best fit.

**Recommendation: a new named slice** (e.g. P23B.11 wall-chain commit scoping)
that consumes P23B.7's affected-extent contract and P23B.4's extent-scan
precedent without reopening either closed slice; owner routes. The slice owns
correspondence scoping + the commit-path acceptance-reuse follow-through, with
D-12/Option-E verdict equality as its acceptance bar. Do not route to P23B.8:
nothing here needs Workers/WASM, and the win is algorithmic (fewer pairs),
not throughput.

## 9. Fix options (NOT implemented — expected gain and risk only)

1. **Scope correspondence to the operation's affected extent** (P23B.7 technique,
   new slice). Derive affected faces/rooms from the plan's created/changed
   walls and run pair tests only for those; whole-document fallback on refuse.
   *Gain:* correspondence 776 ms → ~10–30 ms node on clear-gap authoring
   (~95% of plan cost removed; browser release est. 2,147 → ~300–400 ms, the
   residual being compile + mesh + snap + history). *Risk:* medium — requires
   the S4-style proof that out-of-extent pairs cannot change the verdict, plus
   keeping D-12 authorization whole-document (it is not hot).
2. **Broadphase bbox reject before exact predicates.** Skip pairs whose
   bounding boxes are strictly disjoint (sound: disjoint boxes share no
   interior; touching boxes still go exact so adjacency semantics are
   untouched). *Gain:* large on separated layouts (matrix fixtures: most of
   100 pairs rejected in O(1); est. 776 ms → ~100–200 ms), smaller on
   overlapping layouts like owner. *Risk:* low — a pure filter; verdicts are
   unchanged by construction.
3. **Room-neutral early-out + commit-path acceptance reuse.** If extraction
   face keys equal the baseline's (no face created/changed/retired), skip
   correspondence + reconcile; separately, thread `planWallChain`'s compile
   through `PreviewCompileReuse` in `commitWallChain`/`commitWallSegment`
   (mirrors the `finalizeWallGeometryCandidate` pattern). *Gain:* clear-gap
   authoring → ~0 ms correspondence; second-compile removal saves ~26 ms on
   every boundary commit. *Risk:* medium-high for the early-out (face-key
   equality must be exactly the reconciler's notion — needs a dedicated
   oracle; a wrong skip silently breaks Room identity); low for the reuse
   half, which is mechanical.
