# Three r175–r186 capability harvest for Museum

**Decision:** remain WebGL-first. Upgrade as a separately gated renderer change; use public TransformControls APIs, native environment rendering and the existing glTF path to reduce implementation work. Reconsider diffuse GI only as a bounded WebGL probe-grid experiment. No P24 plan amendment or application change is made by this report.

Upstream unit tests were inspected, not executed. ## Upgrade hazards and release coverage

The upgrade is eleven release transitions. Do not combine it with material retuning, new GI, new asset recipes and a renderer migration: isolate the r175/r186 comparison first. The following source-backed checkpoints cover the entire interval; the secondary guide also flags unrelated addon removals to search before changing dependencies.

| Release | Relevant check |
|---|---|
| r175 baseline | Existing WebGL PBR, helpers, PMREM, Draco/Meshopt/KTX2, SSAO/GTAO, instancing and bounds are not new benefits. r175 already requires a DOM element for Controls.connect. |
| r176 | GLTFLoader removed WebP/AVIF support detection: decode failures must reach asset fallback. Capsule argument naming/Lottie deprecation are conditional import-audit items. |
| r177 | ColorManagement conversion methods renamed; Object JSON became 4.7. No reason to migrate Museum persistence. |
| r178 | TransformControls colors are public. Multiply/Subtractive blending requires premultiplied-alpha review if introduced. Batch demo is external-library composition. |
| r179 | `reverseDepthBuffer` became `reversedDepthBuffer`; Timer moved to core. Existing standard-depth Canvas does not need a depth-mode change. |
| r180 | RGBELoader→HDRLoader; RGBMLoader removed. No current Museum HDR imports found, so start new work with the current API. |
| r181 | PBR multiscattering and PMREM filtering alter rough/metal appearance. WebGPU initialization/async API transition matters to experiments, not existing WebGL Canvas. |
| r182 | Major shadow implementation/output-buffer changes. At r186 classic WebGL logs a warning and maps PCFSoft to PCF; do not rely on Threlte’s old default. |
| r183 | Pivot and KHR Meshopt; RenderPipeline rename. RoomEnvironment placement and Sky gamma correction changes make new preset comparisons version-sensitive. |
| r184 | Environment/background rotation alignment; WebGL probes, node compatibility, HTMLTexture. Existing future yaw conventions must be tested with a recognizable HDRI orientation. |

Direct shader diff shows no change in `src/renderers/shaders/ShaderChunk/tonemapping_pars_fragment.glsl.js` between r175 and r186. This **does not** guarantee identical images: BRDF, PMREM, environment rotation, shadows and compositing changed. The upstream editor’s switch to Neutral tone mapping is not the Museum/Threlte default. Keep AgX initially; evaluate a different tone mapper only as an explicit product decision.

**Threlte gate:** upgrade `three` and matching `@types/three` together; verify one resolved Three copy in both apps and all addon imports. Installed renderer factory is synchronous, while WebGPU needs initialization; any async adapter must fit Threlte’s render task and teardown. Its `.dispose()` duck typing changes behavior on r186 even with unchanged app code. Scope/refcount cleanup cannot be inferred from peer ranges.

**Known post-tag caution:** [02198fbc4b / #34522](https://github.com/mrdoob/three.js/commit/02198fbc4b89b52c3a218ca2921c70dbec74d360) changes cube-depth texture allocation/disposal after r186. Reproduce point-shadow delete/recreate and Canvas teardown against the exact candidate package before production approval. If it fails, use a separately verified patch release/backport or defer the upgrade; do not quietly test HEAD and claim r186 passed. Other post-tag WebGPU disposal fixes are likewise excluded from an r186 compatibility claim.

## A. Highest-leverage upgrades

1. **Public gizmo configuration (01):** the clearest deletion opportunity; replace the palette walker and use documented handle policy switches within the existing host.
2. **Native HDRI/PMREM plus explicit output policy (03/05):** delivers accepted gallery-lighting intent without a custom lighting engine. Asset/schema parity remains the actual implementation work.
3. **Keep and strengthen the glTF/decoder pipeline (04/07):** use KHR Meshopt correctness and benchmark compressed derivatives; preserve canonical acquisition, identity and publication scope.
4. **Native light-helper geometry (02):** cheap meaningful authoring feedback; Museum still owns handles, ranges, units and history.
5. **WebGL LightProbeGrid experiment (11):** newly makes indoor diffuse GI worth a small trial without a renderer migration. It does not warrant making GI a P24 gate.

## C. P24 changes warranted by evidence — proposals only

Separate canonical environment asset/intensity/rotation/background/exposure intent from derived PMREM/GI caches. Share the mapping between editor and canonical visitor paths; document any editor assist lighting explicitly.
- **R7/B4:** permit bounded LightProbeGridWebGL and SunLight studies as non-blocking depth. Keep area lights/IES and production GI outside the minimum until evidence justifies them. Unit labels must distinguish point/spot candela, area-light nits and any deliberately normalized preset controls.
- **R7/B4 correctness:** current `EditorLightInspector.svelte`, `editor-lights.ts::validateLightAngle` and `scene-codec/parse-entities.ts` accept spot angles through π; Three’s SpotLight documents a maximum half-angle of π/2 at both r175 and r186. Resolve the semantic range and treatment of existing out-of-range data before adding cone helpers (`tan(angle)` becomes misleading). This is an existing mismatch, not an upgrade regression.
- **R9/B6:** add the renderer upgrade acceptance gate below and repeat the post-P23 coordinate/ownership check. The source audit closes backend capability questions, not visual quality, lifetime or publication parity.

## D. P25 implications

The accepted Destination/Stop/Content/Interaction model remains unchanged. Three does not supply Museum reference validation, semantic `Activate`, responsive Info Panel focus behavior, reduced-motion arrival equivalence or canonical publication semantics. HTMLTexture’s underlying DOM is promising for a future in-world kiosk requirement, but it is not cheaper than the already-selected ordinary DOM panel today. Animation improvements can reduce implementation effort for a later animated exhibit; no evidence makes narration, video, branching or a second timeline part of the minimum. All future exhibit/media references still use the shared project registry. Better P24 light/asset fidelity benefits P25 scenes without changing Experience ownership.

## E. Renderer strategy

**Production:** WebGLRenderer + Svelte 5 + Threlte, native PBR/glTF, explicit color/shadow policy, direct lighting + optional HDRI. Adopt the small substitutions independently after acceptance. Exact r186 promotion is conditional, especially on the point-shadow disposal gate; there is no current performance evidence requiring an upgrade at any cost.

**Experiments:** WebGL probe GI and, if relevant, SunLight first. Then one opt-in WebGPU platform fixture covering Threlte initialization, imported materials, helper exclusion, shadows, resource lifetimes and visitor parity. WebGPU with a WebGL backend is a different renderer integration from classic WebGLRenderer. The r184 node compatibility addon is a limited bridge, not automatic access to SSGI/VXGI. Promote a renderer only for measured product benefit across supported devices; do not plan a migration merely to use newer examples.
