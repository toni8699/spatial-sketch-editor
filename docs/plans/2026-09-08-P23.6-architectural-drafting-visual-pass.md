## Parent contract (durable, from umbrella)

Presentation/interaction projection **only**. No durable Layout fields, no
second Plan geometry model, no new selection system, no consumer-owned
geometry. `PlanRenderModel`/compiled query data remain the source;
`PlanSvg.svelte`/existing Plan chrome remain the renderer. If a visual
affordance needs semantics that are not authored (door handedness, persistent
dimension annotations), omit it rather than smuggling new truth into
presentation state.

## Preserved implementation detail (pre-evidence seed)

### Visual language (all derived presentation)

- **Walls:** strengthen authored wall/room boundary hierarchy; selected/hovered
  walls unmistakable without changing hit authority or geometry. No decorative
  centerlines implying a second editable wall representation.
- **Rooms:** restrained fill/boundary hierarchy + existing room name where
  legible; selected-room emphasis must not overpower wall/opening editing.
  Room labels are derived presentation, never persisted layout text.
- **Openings:** doors/windows read as intentional gaps/symbols; selected-only
  body/width handles matching P23.3. No door swing/hinge/handedness graphics
  until those semantics exist in authored data.
- **Dimensions:** selected straight-wall length and rectangular-room dimensions
  use a consistent architectural treatment — extension lines/ticks, concise
  meter labels, edit affordance where editable. No persistent annotation
  system; nonselected dimensions may be suppressed when density would obscure.
- **Snapping/guides:** endpoint/midpoint/intersection/nearest-span/orthogonal
  winners get distinct compact markers; the marker describes the semantic
  winner, never becomes selection.
- **Objects:** footprints keep authored/selected/hover hierarchy; passive Scene
  footprints stay quieter than Layout-owned editable objects and never gain
  Layout hit authority.
- **Grid:** preserve configured metric step; improve major/minor hierarchy and
  zoom readability; authored snap step and world coordinates never change with
  the drawing treatment.
- **Invalid/preview states:** invalid candidates, direct-manipulation previews
  and snap/alignment previews visually distinguishable from committed geometry
  without mutating documents.

### Tokens and constraints

- Reuse P21 theme tokens and Plan paper identity; no new CAD theme, no
  hard-coded per-theme palettes, no decorative gradients/shadows. Structural
  hierarchy via stroke weight/opacity/pattern/dash + existing semantic tokens.
- Keyboard focus visibility and contrast across all shipped editor themes.
- Label/dimension placement: simple offset/collision avoidance fine; no general
  annotation-layout solver. On conflict, selection/context priority wins;
  lower-priority presentation may hide.

## Tests and fixtures (seed, pre-H2)

- Wall/room/opening/object hierarchy readable across shipped themes and
  representative zooms (50%/100%/200%).
- Selected/hover/preview/invalid states distinct.
- Selected wall/room dimensions and snap markers legible without persistent
  annotation state.
- Passive Scene footprints visually subordinate and non-authoritative.
- Changing visual density/zoom does not change snap coordinates, compiled
  geometry, document JSON or history.
- Focused render-model/component assertions on stable semantic
  classes/attributes; no raw-SVG/pixel snapshot as the only gate.
