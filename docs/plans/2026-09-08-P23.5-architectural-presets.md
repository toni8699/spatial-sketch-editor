# P23.5 — Small architectural preset set

**Parent:** [P23 — Layout Depth umbrella](2026-09-07-P23-layout-depth-minimum-build.md)  
**Status:** `implementation-ready` — blocked by Foundation Gate F0; otherwise independent of topology depth.  
**Evidence:** current Layout object seams sufficient; wall-first reconciliation ratified 2026-09-09.

## Outcome

Provide three useful labeled creation presets over existing document-level Layout object kinds without creating a second architectural system.

Presets:

- **Column** → cylinder;
- **Platform** → box;
- **Plinth** → box.

## Contract

A preset is only a creation default.

```text
choose preset
→ create ordinary LayoutObject with preset defaults
→ edit through normal Layout object controls
→ compile/render like every other LayoutObject
```

No preset-specific serialized kind, linked instance, library service or downstream renderer branch.

`LayoutObject[]` remains document-level and project/world-local after F0.

## Placement

Reuse canonical Layout object placement/validation.

- floor-relative placement may use an explicit Floor reference/height context when required by the operation;
- stored object transform remains project/world-local;
- no mandatory Room containment;
- exterior objects remain valid where product geometry permits;
- cancellation/invalid placement leaves no history.

Do not move Layout objects under `LayoutFloor` merely because placement references a floor surface.

## Dimensions

Each preset exposes kind-appropriate editable dimensions through P23.1/existing object controls.

Suggested defaults are an implementation/product eye-call and must be finite/positive. Defaults do not become semantic constraints after creation.

## Partition is not a preset

Do **not** ship a generic box preset named `Partition`.

Wall-first P23 now has a real first-class `LayoutWall.role = 'partition'` authored through P23.9. A box preset would:

- fail to participate in canonical Wall topology;
- fail to host Openings canonically;
- imply a misleading second physical wall concept.

A future freestanding display-fixture template may be added under an explicit fixture/template product concept if needed, but it is not architectural Partition truth.

## Compiler / visitor

Preset-created objects flow through the existing/evolved canonical Layout compiler exactly like equivalent ordinary objects.

No preset code belongs in visitor runtime after document creation.

## Tests

- Column compiles/round-trips as ordinary cylinder object;
- Platform/Plinth compile/round-trip as ordinary box objects;
- presets create document-level/world-local Layout objects;
- dimension edits use existing/P23.1 object semantics;
- floor placement respects elevation without introducing Floor ownership;
- cancellation creates no object/history;
- serialized JSON contains no preset-only durable metadata;
- Plan/3D/visitor output equals equivalent manually created primitive.

## Non-goals

- preset editor/library;
- linked prefabs;
- user preset catalogue;
- fake box Partition;
- Scene asset templates;
- new primitive geometry kinds.
