# P23.4 — Duplicate and linear repeat

**Parent:** [P23 — Layout Depth umbrella](2026-09-07-P23-layout-depth-minimum-build.md)  
**Status:** `implementation-ready` — blocked by Foundation Gate F0; Opening repeat also depends on P23.3.  
**Evidence:** current verified mutation/history seams + H1/H5 lineage guidance; wall-first reconciliation ratified 2026-09-09.

## Outcome

A creator can duplicate or linearly repeat supported Layout records deterministically without creating shared mutable aliases, stale topology references, or Scene/Camera side effects.

## Supported targets

Initial minimum:

- one supported document-level Layout object;
- one Wall-hosted Opening on its current Wall;
- one **isolated** Room whose bounded Wall/Junction/Opening subgraph can be cloned without detaching shared architecture.

Duplicate is repeat with one copy.

Repeat count remains bounded to `1..50` unless measured evidence justifies changing the cap.

## General clone contract

Use a two-pass deterministic clone/remap flow:

```text
collect source graph in stable order
→ allocate all new IDs
→ build old→new maps
→ clone
→ remap internal references
→ apply per-copy transform/offset from original source
→ validate complete batch
→ commit once
```

Never generate later copies from the preceding copy; use `index × delta` from the original to avoid accumulated rounding/drift.

No timestamps/random IDs.

Any invalid copy rejects the whole batch.

## Layout object duplicate/repeat

`LayoutObject[]` remains document-level and project/world-local.

For one supported object:

- creator provides X/Z translation delta;
- preserve Y, rotation, dimensions and kind-specific data unless the operation explicitly changes them;
- each copy receives unique deterministic ID;
- optional semantic Room context, if still present after F0, must not become required transform ownership;
- do not infer/change Floor ownership by coordinates.

Profile/read-only object restrictions remain explicit. Do not silently strip unsupported data.

## Opening duplicate/repeat

Openings repeat along one canonical hosting Wall.

Input:

- copy count;
- spacing in physical meters along canonical Wall direction.

For copy `i`:

```text
newOffset = source.offset + i * spacing
```

Rules:

- preserve kind/width/height/sill/profile;
- new Opening IDs deterministic;
- host remains the same Wall;
- validate the **entire final opening set on the Wall** against existing/new intervals;
- overflow/overlap rejects the whole batch;
- negative spacing may be allowed if it remains deterministic and fully validates; otherwise reject explicitly rather than normalize silently.

### Portal relations

Do not blindly duplicate `connectsRoomIds`.

A duplicated door relation is preserved only if the copy remains on the same hosting Wall and the same two physically adjacent Rooms satisfy the new-schema portal contract at the copy's location. Otherwise reject the batch or require relation removal before duplicate.

Legacy compatibility openings are read-only until migrated/resolved.

## Isolated Room duplicate

Room no longer owns its physical structure, so Room duplication means cloning a bounded subgraph.

Eligible initial case:

- target Room is enclosed by a Wall/Junction subgraph that is not shared with another persistent Room in a way that would require detaching/copy-on-write semantics;
- hosted Openings and supported Layout structure inside the cloned subgraph can be remapped deterministically;
- no unresolved external portal relation crosses from the cloned subgraph to non-cloned Rooms;
- no read-only legacy compatibility geometry is involved.

Clone:

- boundary Junctions;
- boundary Walls exactly once;
- Wall-hosted Openings exactly once;
- persistent Room record with a new ID/name;
- supported document-level Layout objects only when an explicit current semantic association says they are part of the room-copy operation.

Do **not** clone Scene entities, clusters, Camera nodes, paths or tours.

## Shared-boundary Room duplicate

Initial P23 rejects Room duplication when the target shares physical Walls with neighboring Rooms such that copying it would require choosing between:

- detaching shared Walls;
- duplicating only one side;
- moving neighboring topology;
- inventing new ownership semantics.

Return a clear unsupported-shared-boundary diagnostic. Do not silently duplicate coincident Walls.

## Room-copy transform

Creator supplies project/world X/Z translation for the cloned subgraph.

- all cloned Junction coordinates use the same exact delta from original;
- Wall IDs/references remap through cloned Junction IDs;
- Opening offsets along each cloned Wall remain unchanged because the cloned Wall geometry moves with them;
- Room identity/boundary references remap to cloned Walls;
- no Room frame parenting is created.

## Selection after success

Preserve existing single-selection model.

Recommended:

- object/opening duplicate selects the first new copy;
- Room duplicate selects the first new Room;
- batch repeat does not introduce multi-selection solely for this feature.

Failed operation restores prior selection.

## History

One duplicate/repeat command → one Layout history result.

Undo/Redo must restore the exact allocated IDs and complete batch snapshot. Redo never reallocates.

## Tests

- N object copies get unique IDs and exact `index × delta` positions;
- object copies remain document-level/world-local;
- Opening copies get exact offsets and unique IDs;
- final Wall opening set validates as one batch;
- invalid last copy rolls back all copies;
- portal relation copies only when new-schema adjacency remains valid;
- isolated Room duplicate clones each Junction/Wall/Opening exactly once;
- cloned Room boundary references only cloned Walls;
- Scene/Camera documents remain byte-equivalent;
- shared-boundary Room duplicate rejects with no state/history change;
- external portal relation blocks/rejects isolated Room duplicate when it cannot be remapped safely;
- 50-copy fixture catches non-finite values, ID collisions and accidental per-copy compile loops where avoidable;
- Undo/Redo restores exact IDs.

## Non-goals

- duplicate arbitrary connected building subgraphs;
- copy-on-write shared Wall semantics;
- Scene/Camera duplication as part of Room duplicate;
- linked prefab instances;
- group/multi-selection repeat;
- geometry cloning that bypasses canonical Wall/Junction records.
