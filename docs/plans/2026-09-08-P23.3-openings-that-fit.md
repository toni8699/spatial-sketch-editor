## Parent contract (durable, from umbrella)

Build on existing door/window offset/width/height/sill/profile controls. Offset
is the opening's start measured in **meters along the segment** — no schema
migration to normalized `t`. Direct manipulation is straight-segments-only with
a stated reason. Reject overflow rather than clamp silently. Curved-segment
behavior remains supported as-is.

## Preserved implementation detail (pre-evidence seed)

### Numeric placement helpers

- Expose segment length and remaining clearance; make clear that offset is the
  opening's start in meters along the segment. Add Center on segment and
  distance-from-end placement by converting to the existing offset
  representation. Reuse rectangular/rounded/pointed profiles; no new door-leaf
  meshes or open/close behavior.

### Direct manipulation (straight segments)

- Dragging the opening body slides it along its owning segment only.
- Left/right width handles resize along that same segment.
- Gesture keeps `segmentId`, height, sill and profile unchanged unless the
  edited field owns that value.
- Transient preview; pointer-up commits one Layout history entry; Escape/pointer
  cancellation restores the immutable baseline with no history.
- Validate the whole candidate: finite positive dimensions, segment limits,
  vertical fit, overlapping opening intervals — canonical geometry
  rules/tolerances. Numeric and direct edits reject overflow rather than clamp.

### Door relations (explicit room choice)

- Expose the existing optional door `connectsRoomIds` through an explicit room
  choice using current codec/portal semantics. The codec already enforces
  doors-only, existing room IDs on both members, and the owning room as
  relation[0] — so the picker offers only valid non-owner room choices instead
  of relying on post-hoc rejection.
- Windows remain unpaired. Do not infer a relationship from adjacency, create
  camera edges, or promise a relation cuts a second wall. Show the actual
  compiled result. Two physical wall openings remain explicit authored openings.
- Changing door/window kind preserves only valid fields; any reset is explicit
  in the UI.
