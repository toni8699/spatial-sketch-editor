## R5 — transform and arrangement

| Capability / proven gap | Disposition and bounded decision |
|---|---|
| Transform, selection, history | **KEEP.** One TransformControls host, Scene adapter, ordered canonical selection and Scene transaction stack. Immutable start matrices drive preview; one completed operation = one entry, cancel/no-op = none. Inspector uses the existing commit facade. No parallel command/history/selection framework. |
| Local/World switch | **POLISH.** Scene policy hardcodes World despite existing session switch. Wire orientation through that policy; World remains default. Local uses the primary object's world orientation, including multi-selection. Capture primary/frame at gesture start; apply one delta to all members. This changes handle orientation, never stored coordinate meaning. Camera/Layout retain their own supported policy; do not blindly apply Scene freedom to them. |
| Pivot | **KEEP Selection Center; DEEPEN Active Object option.** Actual code centers the combined world bounds of all roots; it is not already an active-object pivot. Single selection copies root orientation. Default preserves combined-bounds center; optional Active Object uses primary world-bounds center. Both are derived session choices, frozen during drag. No origin rebasing, stored pivot, cursor pivot or native-pivot migration. Local orientation and pivot location are independent. |
| Scale correctness | **POLISH minimum; FOLLOW-UP independent-scale persistence.** `writePlacementTransform` persists the average scalar of independent axes, so the visible shape cannot round-trip. Minimum exposes uniform positive scale only and clearly disables independent mode until canonical codec/runtime/history/PlanProxy parity exists. Do not silently collapse existing session vectors during save: require an explicit conversion choice or block with reason. Per-axis schema work is a separate R9 promotion, including rotated multi-object shear counter-cases; matrix decomposition is not proof that arbitrary nonuniform group scaling is representable. |
| Inspector/primary feedback | **POLISH.** Show primary identity and effective frame/pivot; numeric commit updates gizmo and vice versa. Mixed transform numerics are **FOLLOW-UP**; selection-wide gizmo operations already serve the minimum. |
| Snap | **KEEP + POLISH.** Reuse current snapping/Shift bypass and R3/R4 view-specific rules. Canonical translation grid is project/world; legacy frame snapping stays explicit compatibility. Local axes do not silently rotate the grid. Show enabled step/bypass and actual winning snap only where the existing operation supplies it; do not invent a winner or new solver. Plan X/Z/yaw preserves Y/pitch/roll/scale. |
| Duplicate | **KEEP + POLISH.** Current code copies primary first, uses deterministic IDs, offsets stored X/Z by +0.5, retains material references, copies complete clusters and selects copies in one transaction. Canonical duplicate keeps +0.5 project/world X/Z and Y. Partial-cluster copies remain ungrouped but report that fact. Validate all candidates before committing; no partial silent success. Duplicate then ordinary Move stays two explicit undoable actions. |
| Collision/support | **POLISH feedback; FOLLOW-UP automatic search.** An overlap is legal staging, not grounds for inventing packing/physics. Report known overlap or unresolved support using existing bounds/R3 queries; do not reject mere room-boundary crossing or auto-move to an unknown floor. Keep Y unless an explicit Drop/keep-on-support operation is requested; that uses R3 support choice, with ambiguity/cancel preserving the document. This narrows the earlier vague “collision/re-ground check”. |
| Repeat ergonomics | **FOLLOW-UP.** Repeat-last-delta, arrays and duplicate-drag need separate invocation/reset/cancel semantics; a fixed-offset duplicate is already deterministic. No hidden repeat state in the minimum. |
| Groups | **KEEP flat clusters + POLISH canonical CRUD.** At most one cluster per entity, no nesting/prefabs/parent transforms. | Arrangement aids | **DEEPEN bounded candidate.** Align world X/Z min/center/max to primary bounds; primary stays fixed. Distribute equal edge gaps along world X or Z for at least three units, retaining extremes; sort by bounds center with stable ID tie-break. Negative available gap refuses with reason. Full selected clusters are rigid units, never expanded into separately aligned members. Partial clusters require explicit member selection and warning. Reject missing bounds/unsupported units atomically. Preserve all rotations/scales/Y; use asset-derived bounds, not helper geometry. Same operation may be invoked in Plan/3D on the same eligible Scene set. No mixed Layout/Scene write. |
| Broader arrangement | **FOLLOW-UP** Y alignment, Local-frame align, arbitrary surface matching, box-select, hide/lock, replacement, packing and array tools. **REJECT** second transform authority, persistent Three scene/pivot state, automatic support links or nested scene-graph adoption. |

R9 recommendation: prioritize honest uniform scale, functional Local/World, canonical grouping and duplicate warnings; add bounded X/Z arrangement and the alternate pivot only with the stated fixtures. No proof here claims those missing operations have shipped.

## R6 — material maturity

Current catalogue has six definitions and five map slots (base color, normal, roughness, AO, metalness). Instances refer to catalogue base plus optional base texture and roughness/metalness overrides. Tint and authored tile size are absent. Make Unique/shared-edit decisions already exist. Inspector resolves one selected object. The effective resolver supplies catalogue color/tile size; texture variants are scoped/refcounted. Model remapping replaces every mesh material with a fresh MeshStandardMaterial, so it is not a slot editor and must not be advertised as preserving imported glass/alpha materials after override.

| Capability | Disposition and minimum semantics |
|---|---|
| Definitions + instances | **KEEP.** Catalogue is discovery/preset presentation; asset-backed definitions add approved P24A map resources to the same resolution model. They are not a second material system. Static-first approved definitions are sufficient; arbitrary provider/import pipelines are not required. Asset bytes/provenance stay registry/supply-owned, authored instance overrides Scene-owned. |
| Native imported appearance | **KEEP.** An unoverridden model retains imported materials. A whole-object material assignment explicitly replaces its appearance across meshes; label that scope before applying. Restore imported/base appearance by clearing the assignment. **FOLLOW-UP** per-slot editing and lossless layered overrides on native GLB materials. |
| Shared vs unique | **KEEP + POLISH.** Shared means multiple entities reference one Scene instance, not that they merely use the same catalogue base. Edit Shared affects all references; Make Unique clones and rebinds selected targets. Show affected usage count, including outside selection, before an explicit shared edit. Never mutate catalogue definitions from the instance Inspector. |
| Tint / reset | **DEEPEN.** Instance base-color/tint override with reset-to-base, combined with base map through the existing renderer color path. Reset means removing an override, not writing a sampled base value. Define white as neutral for supplied color maps; verify approved definitions' fallback colors do not accidentally tint them. |
| PBR controls | **KEEP** roughness/metalness with reset; **DEEPEN** approved asset-backed five-slot definitions. Map wiring/channel/UV requirements are supply acceptance, not end-user graph editing. **FOLLOW-UP** arbitrary per-map uploads/strength panels, authored transmission and advanced physical controls. Preserve native imported alpha/transmission where no override is applied. |
| Texture size | **DEEPEN bounded.** Positive physical tile width/height for surfaces with known metric UV mapping, using existing repeat calculation. For arbitrary GLB UVs, label dimensionless repeat where supported or disable with reason; bounding-box size alone does not establish metres per UV tile. Keep consistent scaling across all mapped slots. No UV unwrap/painting or automatic projection claim. |
| Multi-selection | **DEEPEN minimum.** Mixed values stay visibly mixed. Apply assignment/patch to selected eligible models/primitives in one transaction; validate all targets before mutation. Mixed unsupported targets refuse with reason rather than silently skip. Default edits isolate selected references from unselected users; for each affected shared instance clone once for its selected subset, retaining sharing within that subset. Explicit Edit Shared deduplicates instance IDs and discloses outside-selection impact. Make Unique per object remains an explicit separate choice. Cancelled choice produces no mutation/history. |
| Catalogue discovery | **POLISH** labels/previews and base/shared/unique/overridden state in existing Library/Inspector. A large material browser or acquisition UI is **FOLLOW-UP**. |
| DCC material scope | **REJECT for P24 minimum** node graphs/TSL editing, arbitrary shader/slot editor, UV tooling, texture painting and retroreflectivity UI. Renderer availability is not user need. |

Material acceptance must cover tint/reset, roughness/metalness/map combinations, physical tile size versus GLB repeat, shared-outside-selection isolation, duplicate sharing, undo/redo, failed resources and cross-project cache isolation. Resolver/cache keys must distinguish every effective texture variant (repeat/rotation/scope); material color changes must not bleed through shared instances. Retain clone ownership, cancellation and refcounts.

Save/Load, unsaved Preview and cold anonymous Publish must resolve the same definitions/resources without editor cache warming or expiring acquisition URLs. P24A supplies retained approved maps with rights metadata; P22 release resolution must include all selected dependencies. Check native glass/alpha plus explicit whole-model override separately; do not demand unsupported transmission from MeshStandardMaterial. No new material authoring entry point may write Layout in a Scene transaction.

## R7 — lighting and environment

Current authority supports point/spot/directional, color, nonnegative intensity, finite positive optional range, spot angle/penumbra and castShadow. Rotation aims spot/directional along local -Z. The editor proxy is an invisible 0.12 m sphere, not a range visualization. Both MuseumScene copies add a fixed ambient 0.2/directional 0.7 rig and fog/background; editor session presets are not authored presets. No authored environment exists.

| Capability | Disposition and minimum semantics |
|---|---|
| Light model | **KEEP** three existing types and rotation-based aim. **POLISH** Room-free creation through R3 canonical placement and Inspector/gizmo synchronization. Light scaling must not imply range/intensity edits; disable meaningless scale handles through existing policy. Plan keeps R4 selected-but-ineligible behavior. |
| Controls / units | **KEEP** color, intensity, range, angle, penumbra, castShadow. **POLISH** point/spot intensity labels as candela without converting stored values; directional intensity remains direct renderer intensity. Finite range is metres. Missing range already means unlimited in runtime; expose explicit Unlimited by omitting range, not writing zero into a codec requiring positive range. |
| Spot angle mismatch | **POLISH correctness.** Canonical value remains half-angle radians; UI says “Cone half-angle (°)” with 0 < value ≤ 90. No halving existing values. Mutator, Inspector and new-authoring validation must agree on π/2. Compatibility reader retains existing larger values unchanged and exposes a named diagnostic; an explicit repair action chooses a valid value in one undoable transaction. No silent clamp on load/save. Existing releases/relic compatibility remains intact; new Publish with unsupported values is blocked pending repair, while editing/export for recovery remain available. Preview must show the compatibility diagnostic and use the same unrepaired rendering path as editor until repair. |
| Helpers | **POLISH minimum** selected point range sphere, spot cone/direction and directional aim indication, plus reliable pick proxy. Finite distances are truthful; unlimited uses a bounded dashed illustrative helper labelled Unlimited. PointLightHelper alone is not a range volume. Helpers are derived/editor-only/nonpersistent. **FOLLOW-UP** dedicated range/cone drag handles; rotation and Inspector suffice, avoiding a second gizmo. |
| Shadow controls | **KEEP** authored castShadow. Map size/bias/quality/decay policy remains system-owned and consistent across Preview/Publish. Report relevant capacity failures; no per-light shadow tuning panel. **FOLLOW-UP** area/IES/temperature/sun/photometric tools. |
| Global environment | **DEEPEN recommended minimum, subject to R9 supply/runtime gate.** One approved static HDRI path using global Scene intent: stable asset identity, lighting intensity, Y rotation, background mode (environment or solid). No per-Room blending. Registry owns bytes; renderer owns PMREM; Scene owns only intent. No authored renderer cache or Three object. |
| Exposure | **FOLLOW-UP.** Environment intensity plus existing light intensity provides the minimum controls. Keep exposure fixed and identical across editor authored view/Preview/Publish; keep AgX/system tone mapping. Promote authored exposure only on a named fixture that cannot be served by these controls, not because Three exposes it. |
| Gallery preset/baseline | **DEEPEN one bounded authored preset.** Creates ordinary lights/environment intent in one Scene transaction, no persistent rig. New authored-lighting mode explicitly replaces the implicit ambient/directional baseline; editor assist lighting is visibly session-only and disabled in authored comparison/Preview/Publish. An absent authored mode preserves legacy baseline/fog/background. Gallery preset is a reset over the complete authored-lighting state, as defined below. Preset orientation/placement derives from explicit project context, not guessed Rooms. |
| Exclusions | **REJECT for minimum** WebGPU migration, new lighting engine, recursive dispose replacement or persisted light rigs. **FOLLOW-UP** GI/probes, area lights, broad HDR formats, custom shadow tooling and environment blending. |

**Gallery reset contract (owner decision):** First application creates ordinary Scene lights plus environment intent. Later **Reset to Gallery preset** explicitly warns that it replaces **all currently authored lights and environment**, including user-created lights and edits made since application. The same replacement warning applies on first use if authored lighting already exists. After confirmation, validate the complete replacement before atomically replacing that state in one Scene transaction. Cancellation or validation failure leaves the document/history unchanged. Undo restores the complete prior authored-lighting state; redo restores the same replacement entities/IDs and environment, without rerunning allocation. Generated lights are ordinary editable Scene entities; no preset ownership, provenance, special group or persistent rig is retained. Save/Load does not change reset scope and no detection of a previous application is required. The reset must also reconcile references to removed light IDs through existing Scene integrity/selection authorities within the operation; it must not leave dangling cluster membership. Non-light entities and their transforms/materials remain unchanged.

Environment must not enter the minimum as a UI-only toggle. P24A approval/retention, loader format, canonical codec, Scene transaction, shared runtime consumption and cold release resolution must all be scoped together at R9. Start with one approved equirectangular HDR format/resolution; no generic HDR upload or P20 image-MIME bypass. If that vertical slice cannot be accepted, explicitly defer authored environment and its preset portion together; do not claim HDRI parity from a warm editor.

Lifecycle contract: generation/cancellation token prevents stale async HDR loads from replacing current intent; replacements retain the last valid rendering until ready, with failure reported. PMREM targets and owned source textures release on replacement/unmount after last use; shared sources remain refcounted/scoped. Renderer caches produce no history. Preserve existing Threlte ownership; no double disposal. Test point-shadow add/delete and the harvest's post-r186 disposal hazard on the exact selected baseline. No dependency bump is implied.

## Acceptance and R9 handoff

Verification on 2026-09-10: six focused existing Vitest suites passed (64 tests): transform, cluster transform, lights, material mutator, material resolver and texture cache. `git diff --check` passed. Documentation-only change; no full build or browser acceptance claimed. Existing tests are baseline evidence only, not proof of these proposed additions. Required implementation fixtures:

1. Off-origin rotated asset and multi-selection: World/Local axes, both pivot choices, stable primary, same rigid world delta, cancel/undo, no persistent pivot. Canonical roomless and explicit legacy-frame cases.
2. Uniform scale round-trip through Save/Load/Preview/cold Publish; independent mode cannot silently author a lossy state. Plan preserves nonowned components.
3. Duplicate complete/partial groups, material reference sharing, known overlap, unresolved support, repeat invocation, deterministic IDs and undo order. Group/ungroup preserves world poses; canonical roomless hierarchy/selectability works.
4. Unequal-size units and rigid groups: align X/Z min/center/max; equal edge-gap distribution with stable ties, fixed extremes, unsupported bounds and negative-gap refusal; no mixed-owner/partial writes.
5. Material mixed/unsupported selection, shared references inside/outside selection, Make Unique, reset, cancelled decision, one transaction; map/tint/repeat parity and native GLB versus whole-object replacement fixtures.
6. Spot half-angle 30° round-trip, exactly 90°, invalid zero/nonfinite/>90° new edits, legacy >90° load/diagnostic/explicit repair/undo/new-Publish block. Finite/unlimited range and rotated -Z aim; helpers absent from visitor and serialization.
7. Same saved scene in editor authored mode, unsaved Preview and cold anonymous publication: approved materials, lights, shadows, and selected HDRI at recognizable 0/90/180° orientations, background modes and intensity. No hidden baseline/assist-light sum.
8. Gallery reset: apply, edit generated lights, add a user light, Save/Load, then reset; explicit all-lights/environment warning and one atomic replacement with no accumulation or ownership metadata. Cancel/failed validation changes nothing; undo restores exact prior state and redo reuses replacement IDs/state. Include grouped lights to prove reference cleanup, preserve non-light content, and verify first use with existing authored lighting receives the same warning.
9. Material/HDR replacement during loading, failure/retry, project/release switches, repeated mount/unmount and light deletion: no stale result, disposed-resource reuse or growing owned GPU resource trend. Device budgets and exact renderer baseline remain R9 decisions.
