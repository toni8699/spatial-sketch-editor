# P23.1 — Precise Wall, Junction and Layout dimensions

**Parent:** [P23 — Layout Depth umbrella](2026-09-07-P23-layout-depth-minimum-build.md)  
**Status:** `implementation-ready` — blocked by Foundation Gate F0.  
**Evidence:** P23-H1 complete; wall-first reconciliation ratified 2026-09-09.  
**Repository baseline:** current numeric Layout object/opening fields remain the implementation starting point; current Room-owned precision behavior is legacy after F0.

## Outcome

A creator can enter exact architectural values without turning Plan into a general constraint solver. Precision edits operate on canonical Junctions/Walls and existing Layout objects, build one complete candidate, validate it, and commit at most one Layout history result.

## Durable input semantics

- meters/degrees are explicit in UI;
- document angles remain radians where current canonical types require radians;
- finite-number validation everywhere;
- positive-dimension checks for physical dimensions;
- blank input is invalid, not zero;
- manual numeric values are exact and bypass gesture/grid snapping;
- Apply/Enter commits one validated result; Escape/cancel restores baseline;
- invalid/no-op creates no history;
- unsupported fields are disabled/explained rather than silently ignored.

## Layout objects

Keep existing project/world-local `LayoutObject` editing and kind-specific semantics.

Supported existing numeric behavior remains the baseline:

- X/Y/Z position;
- supported rotation;
- box/plane/cylinder/sphere kind-appropriate dimensions/radius;
- profile/read-only restrictions where already applicable.

Do not move Layout objects under Floors or make Room containment required for numeric object transforms.

## Junction coordinates

Expose exact X/Z for supported `LayoutJunction` selection.

Changing a Junction plans the **entire affected Wall network**:

1. move selected Junction candidate;
2. preserve Junction ID;
3. update connected Wall geometry implicitly through endpoint references;
4. validate zero/tiny Walls, intersections/noding assumptions, openings and Room topology;
5. run P23.8 Room reconciliation for affected components;
6. commit once or reject once.

Do not duplicate a Junction merely to satisfy one Wall edit.

## Exact straight-Wall length

Expose exact length in meters for a straight Wall with explicit fixed endpoint:

```text
Fixed: Start | End
```

Rules:

- preserve Wall ID;
- preserve fixed Junction coordinates/ID;
- move the opposite Junction along the existing Wall direction;
- do not silently reverse canonical Wall orientation;
- preserve physical-meter opening offsets;
- reject if resulting opening fit/topology is invalid;
- if the moved Junction is shared with other Walls, validate the whole affected network rather than pretending the Wall is isolated.

If moving a shared Junction would create an unsupported/ambiguous topology component, reject with an explicit reason.

## Wall angle

For supported straight Walls, expose exact angle only where the operation can be defined unambiguously with one fixed endpoint.

- angle is measured in the canonical Plan/world X/Z convention documented by implementation tests;
- preserve Wall ID and canonical start/end direction;
- fixed endpoint remains fixed;
- opposite Junction moves to satisfy current Wall length unless the UI explicitly edits angle+length as one operation;
- shared-Junction network consequences validate through P23.8;
- no persistent angular constraint is serialized.

If implementation evidence shows angle editing creates too many ambiguous network edits for the minimum, keep angle readout and defer mutation rather than inventing a solver.

## Wall thickness

If wall-first schema exposes per-Wall thickness in F0, numeric thickness is editable for supported straight/compatibility-safe Walls.

- finite positive value;
- preserve Wall ID/openings;
- compiler validates joins/cuts;
- does not change Room identity by itself;
- legacy compatibility Walls that are read-only remain non-editable.

Wall height remains floor-derived unless F0 deliberately makes height an authored per-Wall field; do not add a second height owner accidentally.

## Add Vertex / subdivision

`Add Vertex` is redefined as P23.8 Wall subdivision, not Room polygon insertion.

Input may be:

- exact meter distance from canonical Wall start; or
- a Plan point projected onto the Wall by the canonical query geometry.

The operation must use P23.8's durable contract:

- original-start fragment keeps old Wall ID;
- second fragment gets deterministic new ID;
- openings rebase or reject;
- oriented Room boundaries update atomically;
- Undo/Redo restores exact IDs.

## Rectangle width/depth

Keep useful “make this rectangular space W × D” precision, but implement it as a bounded multi-Wall/Junction operation rather than a Room-owned frame resize.

Enable only when:

- the target Room face is a verified simple four-straight-Wall rectangle;
- the required moved Junction/Wall set is deterministic;
- no unsupported shared-boundary/neighboring topology rewrite is required;
- all affected correspondence components are supported by P23.8.

Operation:

- preserve existing Wall/Junction IDs where the same authored records remain;
- move required Junctions to reach exact dimensions in the rectangle's local axes;
- do not scale Scene/Camera or Layout objects;
- opening offsets remain physical meters and must still fit;
- whole affected network validates before one commit.

If shared Walls make the requested resize ambiguous, reject rather than detaching/duplicating architecture silently.

### Fixed anchor and dimension axes

Rectangle resize takes an explicit `anchorJunctionId` and incident `widthWallId`. The anchor stays fixed. The width axis points from that anchor toward the width Wall's other endpoint; the depth axis points toward the other incident boundary neighbor. These are rectangle-local geometric axes, not a persisted Room frame or the Wall's canonical opening direction.

When the user has not chosen references, default to the smallest stable Junction ID on the face, then the smallest stable incident boundary Wall ID as width. Show/highlight both references before Apply. Capture them for the numeric draft; do not reselect axes during preview. If either reference becomes invalid, cancel the draft.

For anchor A, unit axes u/v, and requested width W/depth D, the four target corners are A, A + W*u, A + W*u + D*v, and A + D*v. Map each to its original Junction ID. This fixes translation and orientation even for a square or rotated rectangle; reversing a Wall's stored direction does not swap the axes. No automatic width/depth swap based on longest edge or world bounds.

## Room frame

`LayoutRoom.frame` is **not** a target authoring primitive after F0's world-space migration. Existing Room-frame controls belong to current/legacy behavior and must be removed, hidden or compatibility-read-only when wall-first writers enable.

P23.1 must not recreate a Room transform parent simply to preserve the old UI.

## Numeric/direct-manipulation parity

Where an equivalent gizmo/Plan gesture exists, both paths must resolve to the same semantic candidate rules.

Examples:

- numeric Junction move == Plan Junction drag candidate;
- numeric Wall length == exact-length draft/resize candidate;
- numeric Layout object transform == existing gizmo transform semantics.

UI may differ; authored result/validation/history must not.

## Tests

- exact Junction X/Z reaches requested coordinate and preserves ID;
- connected Walls update through same Junction identity;
- invalid shared-Junction move rejects atomically;
- exact Wall length with Start fixed;
- exact Wall length with End fixed;
- Wall ID survives;
- opening offsets remain in meters and invalid fit rejects;
- supported exact angle reaches requested orientation;
- Wall thickness round-trip where enabled;
- Add Vertex uses P23.8 subdivision IDs/rebasing;
- simple rotated rectangle reaches requested local width/depth with the selected anchor unchanged;
- square rectangle, reversed Wall direction and reordered record arrays retain the same reference axes/corner mapping;
- explicit reference override uses the selected anchor/width edge; invalidated draft reference cancels;
- shared-boundary ambiguous rectangle resize rejects;
- Layout objects/Scene/Camera remain physically unchanged during architecture sizing;
- blank/non-finite/zero-invalid input leaves state unchanged;
- one Undo/Redo restores exact IDs/values.

## Non-goals

- numeric curved-Wall length mutation;
- general parametric constraints;
- dimension dependencies that persist after Apply;
- automatic neighbor-room solving;
- Room-frame parenting;
- floor-wide height/elevation expansion unless independently planned;
- multi-selection dimension editing.
