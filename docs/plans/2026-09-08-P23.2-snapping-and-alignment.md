## Parent contract (durable, from umbrella)

Extend the existing Plan snap controls, not global editor preferences. Snap
candidates derive from `CompiledLayoutGeometry.queries` plus transient gesture
guides — Plan/SVG code must not independently reconstruct or resample authored
geometry to create another snap truth. No persistent constraints are serialized.
Alignment is initially one selected supported object to one reference. Must not
touch Scene/Camera snapping or existing angle modifiers.

## Preserved implementation detail (pre-evidence seed)

### Grid step

- Keep the current 0.25 m default; expose a finite positive grid step with the
  existing input-validation pattern. Reconcile the hard-coded quarter-meter
  paths so the selected step applies to affected Layout placement and
  translation gestures.

### Snap candidates and acquisition

- New semantic snap candidates derive from compiled query records plus transient
  gesture guides. Linear scan first; a spatial index only after measured
  project-size evidence (RBush/Flatbush stay deferred per research).
- Reference snapping for room drafting/vertex edits and supported object/room
  translation: boundary endpoints/room corners; straight-wall midpoints;
  wall/reference-span intersections where valid; nearest point on a
  wall/reference span; orthogonal guide relative to the active anchor; opening
  edges while editing an opening; rotation-aware object bounds edges/centers in
  X/Z where already supported.
- Exclude the moving target and its owned members.
- Fixed CSS-pixel acquisition radius, stable across zoom (worldRadius =
  snapRadiusCssPx / planScale; research T4). Model-space geometry tolerances are
  a separate canonical policy — never one shared EPSILON.
- Priority: tool/context validity → semantic feature priority → screen distance
  → stable ID/key. Reference snap wins over grid when acquired. Deterministic
  tie-breaks (research T5).
- Visible guide/marker identifies the winner; snap-off disables both; guides
  clear on cancel (research T6). Reject invalid geometry rather than silently
  moving to a different candidate.

### Alignment

- One selected supported layout object to one reference: another supported
  layout object's world AABB, a room's compiled Plan bounds, or a selected
  straight-wall reference. Choose X or Z and minimum/center/maximum for bounds
  references; wall reference adds a bounded **Center on wall** action using
  compiled/query geometry.
- Translate only the selected object, preserving height, rotation, dimensions
  and ownership. Inspector reference picker keeps the active selection intact.
- No-op alignment adds no history. General distribution/group alignment is
  later (follow-up list).
