## Preserved implementation detail (pre-evidence seed)

### Geometry robustness policy (umbrella contract, fixture targets here)

- Four separated tolerance classes: pointer/snap acquisition (CSS px through
  Plan zoom); minimum authored size (meters, operation-specific); geometric
  equality/degeneracy (canonical layout-core policy/helpers); display rounding
  (UI only). Never one magic EPSILON for both pointer UX and topology.
- Deterministic behavior around near-collinear/nearly coincident cases.
- If current line/intersection math fails the acceptance fixtures, prefer a
  focused `robust-predicates` adapter in `layout-core` (Unlicense — the one
  permitted focused dependency) before any broad geometry framework.
  Flatten.js/JSTS stay research references unless a bounded missing capability
  earns them.

### Degeneracy fixture set (from umbrella acceptance; provenance via H3)

- near-collinear intersections;
- nearly coincident endpoints;
- zero/tiny wall length;
- endpoint intersection;
- deterministic snap ties;
- opening-invalidating wall resize.

### Manual integration fixture (owner-facing, whole-slice)

Create a rotated 6 m × 4 m room, set a 0.1 m grid, set one straight wall to an
exact requested length, place a column and platform, align one object to bounds
and another to a straight wall, add a centered 0.9 m door, drag it along the
wall, resize it with a width handle, add a window with a sill, repeat three
columns, duplicate the unlinked room, edit one copy independently. At 50%/100%/
200% Plan zoom inspect wall/room/opening hierarchy, dimensions, grid density,
snap markers, selected/hover/preview states, passive Scene-footprint
subordination. Check Plan/3D, Undo/Redo, project switching, Preview return.
Save/Load and portable export/import retain dimensions, IDs, ownership and
opening relations. Publish through P22 and inspect in a fresh unauthenticated
browser; later Layout edits leave the old publication unchanged until Update.
