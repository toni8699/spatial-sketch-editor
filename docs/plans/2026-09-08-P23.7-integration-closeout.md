# P23.7 — Integration, compatibility and closeout

**Parent:** [P23 — Layout Depth umbrella](2026-09-07-P23-layout-depth-minimum-build.md)  
**Status:** `implementation-ready` — runs last after P23.0/P23.8/P23.1/P23.2/P23.9/P23.3/P23.4/P23.5/P23.6. P23.1 and P23.2 are already shipped on `main` (PRs #9 / #13); P23.9 is the current slice.  
**Evidence:** H1/H2/H3/H5 complete; wall-first reconciliation ratified 2026-09-09.

## Outcome

P23 closes only when wall-first authoring, exact identity/history, migration/compatibility, Preview and Publish all work through one canonical Layout compiler/runtime path without regressing Scene/Camera/editor/visitor boundaries.

P23.7 is **not** the owner of topology robustness anymore. H3 topology is foundational in P23.8. This slice owns whole-product integration and final regression/compatibility gates.

## Manual owner-facing Build fixture

Start from an empty Floor and complete this flow:

```text
1. draw an outer boundary-Wall loop
2. verify one persistent Room appears
3. draw a complete internal boundary divider
4. verify the original Room becomes two Rooms with H5 identity rules
5. add one Door to the shared Wall
6. verify one physical Opening/cut serves the shared Wall
7. add one interior Partition
8. verify physical Wall appears but Room count does not change
9. set exact Wall/Junction dimensions
10. use non-default grid + semantic snaps
11. add Column + Platform/Plinth
12. align a supported Layout object to bounds/Wall
13. repeat supported Opening/object records
14. duplicate one eligible isolated Room/subgraph and edit it independently
15. place/retain a Scene object outside every Room
16. place/retain a Camera node outside every Room
17. edit/move architecture and verify Scene/Camera world placement does not move implicitly
```

Exercise Plan at representative zooms and 3D in the same project.

## Room identity acceptance

Include deterministic automated fixtures for:

- lineage-preserving 1→1 deformation;
- Wall subdivision;
- asymmetric 1→2 split;
- exact-tie 1→2 split;
- unequal 2→1 merge;
- equal-area 2→1 merge;
- merge metadata conflict rejection;
- Room disappearance/open enclosure;
- one command with several independent supported correspondence components;
- one command with one unsupported many↔many component rejects atomically;
- split/merge → Undo → Redo restores exact Room/Wall/Junction/Opening IDs.

No Redo path reruns correspondence/ID allocation.

## Geometry/topology regression

Use P23.8/H3 fixtures, including:

- near-collinear orientation/intersection cases;
- nearly coincident but distinct Junctions do not auto-connect;
- endpoint/T/X classification;
- collinear overlap rejection;
- zero/tiny Wall rejection;
- dangle/cut-edge diagnostics;
- invalid ring;
- unsupported nested/hole topology;
- opening-invalidating Wall split/resize.

Interaction acquisition tolerance remains separate from topology validity.

## New-schema portal acceptance

- valid two-sided shared-Wall door relation survives Save/Load;
- nonadjacent new-schema relation rejects;
- split remaps relation to actual adjacent descendant;
- merge collapsing both semantic endpoints clears relation explicitly;
- ambiguous remap rejects;
- physical Opening survives when relation is intentionally cleared.

## Legacy Project migration acceptance

Maintain frozen/representative legacy fixtures.

### Lossless migration

- isolated legacy Room preserves Room ID;
- compatible shared straight boundary collapses to one Wall;
- reversed boundary normalizes opening offset correctly;
- compatible paired opening records collapse deterministically;
- Scene entity world position preserved;
- Scene entity arbitrary world rotation preserved;
- clusters preserve grouping/member IDs without Room spatial ownership;
- Camera eye + target preserved;
- Camera path anchors/waypoints/view-key targets preserved;
- migrated project validates before install;
- migration establishes editor history baseline rather than user-visible migration commands.

### Trustworthy frame context

- legacy full Project uses its own decoded Layout Room frames and succeeds;
- standalone legacy Scene + explicitly supplied trusted frame mapping succeeds;
- standalone legacy Scene + merely matching IDs in current Project does **not** count as trusted source context;
- standalone legacy Scene without trusted frame context rejects with specific diagnostic;
- wrong/partial mapping rejects before install.

### Double-transform regression

- read-only legacy-compatible Scene resolves through its retained Room frame exactly once for Preview/visitor;
- migrated/new world-local Scene bypasses Room transform resolution;
- same authored placement renders at the same world matrix before/after lossless migration;
- visitor and editor Preview agree.

## Legacy conflict/read-only compatibility acceptance

### Coincident walls/openings

Fixtures:

- compatible exact shared walls migrate;
- conflicting thickness remains readable but not wall-first-saveable;
- one-sided/conflicting opening remains readable but not wall-first-saveable;
- curve-definition conflict remains compatibility-only;
- no silent first-record/Room-order winner.

Read-only compatibility must still flow through the one shared runtime/compiler output path.

### Curves

- representative `auto-bezier` legacy wall/Room keeps authored appearance/placement;
- no flattening during compatibility preparation;
- unsupported curve topology editing is disabled with explicit reason;
- old publication using curves remains cold-loadable.

### Legacy portal semantics

- previously valid nonadjacent `connectsRoomIds` remains readable under legacy compatibility;
- old publication continues loading;
- relation is not silently cleared;
- migration report marks it unresolved for new schema;
- new-schema Save is blocked until explicit resolution/removal.

## Save / Load

After F0 writer enable:

- new editable projects save explicit new Layout + Scene format identifiers;
- new Scene stores project/world-local spatial meaning;
- wall-first save round-trip preserves all Junction/Wall/Opening/Room IDs and object transforms;
- migrated legacy Save creates a **new** canonical saved version; old stored versions remain immutable/history records;
- ambiguous compatibility-only Project cannot silently save as new schema.

Cloud save revision is not treated as schema version.

## Standalone package acceptance

Current `.scenepack` is Scene-focused. P23 closeout must prove both compatibility and new behavior:

- new package exports explicitly identified world-local Scene data;
- import does not require Room frames for new packages;
- legacy package with trustworthy frame mapping can migrate;
- legacy package without trustworthy frame context rejects clearly;
- package format version and Scene schema version are validated as separate concepts;
- texture/binary round-trip behavior remains intact.

Do not silently use currently open Room frames just because IDs match.

## Preview

Draft Preview consumes the same canonical in-memory Project candidate the editor would Save.

- no Preview-only migration rules;
- no second geometry compiler;
- world-local Scene remains world-local;
- legacy compatibility Preview uses explicit compatibility runtime preparation and is read-only;
- current camera route/motion system remains the only Camera evaluator.

## Publish / visitor

Use P22's immutable publication/version model.

Acceptance:

```text
legacy published snapshot
→ shared compatible decode/runtime preparation
→ canonical compile/runtime
→ cold anonymous visitor
```

and:

```text
new wall-first published snapshot
→ new-schema decode
→ canonical compile/runtime
→ cold anonymous visitor
```

Requirements:

- never rewrite old published JSON in place;
- old release appearance/navigation remains equivalent for preserved features;
- visitor bundle does not import editor selection/history/gizmo/import-management code;
- no visitor-specific geometry/migration fork;
- new publish/update creates a new immutable saved/release version.

## Editor-adapter regression

Re-run the F0 adapter inventory to prove no stale Room-owned mutator survived writer enable.

### Wall/Junction/Opening selection cutover acceptance

P23.7 owns proving the cutover is complete: no stale Room-owned selection/hit
path remains authoritative.

- one canonical selection authority carries Wall/Junction/Opening targets
  (extended by P23.6, accepted here) — no second selection store, no parallel
  hit-test path, no renderer-local selection model;
- a legacy `(roomId, segmentId)` selection cannot outlive the cutover: it is
  reconciled/demoted explicitly and never silently resolved to a winner;
- canonical Wall/Junction selection, hover and editing affordances behave
  identically on shared Walls and on roomless/Partition Walls;
- P23.3's minimal canonical Opening target remains the Opening authority once
  the cutover lands (no room-scoped re-introduction);
- legacy compatibility selection stays read-only and visibly unavailable
  rather than mutating new records;
- closeout records the old selection/hit paths that were deleted or disabled.

## Final architecture assertions

Close P23 only if all remain true:

1. `LayoutDocument` and `SceneDocument` are separate authored domains.
2. New physical architecture is Junction/Wall/Openings; Rooms are persistent semantic regions.
3. Layout objects remain document-level/project-world-local.
4. Scene/Camera physical placement is project/world-local in the new schema.
5. No topology edit implicitly moves staged content.
6. One canonical `compileLayoutGeometry()` family feeds Plan/3D/visitor.
7. One canonical selection/history system remains active.
8. One Camera graph/route/motion system remains active.
9. Legacy compatibility is shared/runtime-safe and old publications remain readable.
10. New writers cannot create old Room-owned geometry.
11. Visitor/editor isolation remains strict.
